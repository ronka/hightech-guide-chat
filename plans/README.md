## What each plan fixes

**001** — Progress bar fills from the wrong side in RTL (measured: fill anchored to the left edge on a `dir="rtl"` page). Every error renders the same generic Hebrew string because the server returns `{ error }` and the client reads `.message`. The system prompt instructs the model to produce `<job_title>`, which the schema cannot return, and then anchors keyword extraction to that non-existent value.

**002** — The score is meaningless without a job description (92 vs 15 on the same CV). Ports the six-dimension weighted rubric from the repo's own `.agents/skills/roast-my-cv` skill, where 50 of 100 points are provably JD-dependent. Adds red-flag detection and makes the UI label a no-JD result as a CV-quality score out of 50 rather than a match percentage.

**003** — CV filenames are sent to PostHog and Facebook (confirmed in the browser console). The endpoint has no bot protection despite `/api/chat` and `/api/auth` having it, and no file size or MIME validation on a paid LLM call.

## Considered and rejected

- **Rate-limit bypass via `x-forwarded-for` spoofing.** I proved it locally — changing one octet resets the daily quota. Rejected as a production vulnerability: Vercel overwrites `x-forwarded-for` and refuses to forward external IPs specifically to prevent this. Downgraded to a documented latent hazard; plan 003 step 4 adds a code comment only. Revisit if a proxy is ever placed in front of Vercel.
- **The 45 `npm audit` vulnerabilities** (2 critical, 27 high). All transitive under langchain/drizzle and not reachable from this feature. Not worth doing as part of this work.
- **Porting the roast-my-cv intake flow** (3–6 targeted questions before scoring). Genuinely valuable, but it is a two-stage conversational product change, not a fix. Left out of 002 deliberately.

## Known deferred items

Real, verified, but not planned. Pick up if they start to matter:

- `src/app/layout.tsx:33` sets `lang="en"` on an all-Hebrew site with `dir="rtl"`. Affects screen readers and search-engine language detection site-wide.
- No `AbortController` or timeout on the client fetch in `cv-analysis-client.tsx`. A hung request spins forever with no way out — the reset button only exists on the results screen.
- `AI_GATEWAY_API_KEY` is absent from the `envSchema` in `src/services/config.ts` while five other variables are validated. A missing key in production surfaces as an opaque 500.
- `results: any` in `cv-analysis-client.tsx:19`. The API response is never validated client-side, so a schema change fails at render time rather than at the boundary.
- The upload area's copy promises drag-and-drop ("גרור ושחרר את קורות החיים כאן") but `file-upload.tsx` implements no `onDrop` or `onDragOver` handler.
- Results are lost on page refresh. No save, share, or export.

## Product direction (not defects)

Two options grounded in what is already in the repo, for the maintainer to weigh:

1. **Suggested rewrites.** The roast-my-cv skill's core output is `Original: "..." → Rewrite: "..."` for every weak bullet. The web tool returns only generic improvement strings. This is the highest-value addition available and is mostly schema plus prompt work.
2. **The Israeli-specific guidance in `references/how-to-write-good-resume.md` is entirely absent from the API prompt** — strip ID number, driving licence, home address, and photo; frame military service as professional experience; avoid star-rating skills; prefer an English CV for Israeli hightech. This is differentiated content from the site's own book and the most natural bridge to the consulting CTA already on the results screen. Plan 002 pulls in the red-flag subset; the rest is unbuilt.
